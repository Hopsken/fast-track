# Fast Track — Design Context

> This doc is the design source-of-truth for AI sessions. Every UI decision should be consistent with the principles here. When in doubt: simpler, faster, quieter.

---

## Personality

**"Fast, precise, quiet."**

Fast Track lives inside Jira — the most bloated, slow-feeling tool in the workflow. The extension's job is to be the antidote: snappy interactions, zero visual noise, keyboard-first. Every pixel should feel like it earned its place.

References: Linear, Raycast, Arc, Vercel dashboard.
Anti-references: Jira itself, Notion (too soft), Todoist (too loud), any SaaS with a purple-on-white gradient hero.

---

## Palette

Pure neutral monochrome in OKLCH. Chroma is always 0 — no synthetic warmth, no tinting. The warmth comes from the website's off-white base (`#fdfbf9`), not from hue shifts.

```css
/* Light */
--background:          oklch(1 0 0)        /* white */
--foreground:          oklch(0.145 0 0)    /* near-black */
--primary:             oklch(0.205 0 0)    /* dark gray */
--muted:               oklch(0.97 0 0)     /* light gray */
--muted-foreground:    oklch(0.556 0 0)    /* mid gray */
--border:              oklch(0.922 0 0)    /* hairline */
--destructive:         oklch(0.577 0.245 27.325)  /* red-orange, only for errors */

/* Website base override */
background: #fdfbf9;   /* warm paper, not clinical white */
foreground: #1c1c1c;

/* Dark */
--primary:             oklch(0.985 0 0)    /* white */
```

**Rule:** never introduce a new hue unless it's `--destructive`. If something needs emphasis, use weight, size, or motion — not color.

## Typography

| Role | Font | Notes |
|------|------|-------|
| UI / body | **Inter** | `--font-sans`; default for all interactive elements |
| Display / editorial | **Crimson Pro** | `--font-serif`; weights 400/600/700; website headings only |

Crimson Pro is the personality differentiator — used sparingly for high-impact moments (hero text, landing page). The extension UI stays Inter-only.

## Spacing & Radius

Base radius: **0.625rem (10px)**.

```
--radius-sm:  6px   (small chips, badges)
--radius-md:  8px   (inputs, buttons)
--radius-lg:  10px  (cards, panels)
--radius-xl:  14px  (modals, popovers)
```

Tight, not rounded. Avoid pill shapes on anything that isn't a tag/chip.

## Motion

Library: **motion v12** (Framer Motion). Pattern: Emil Kowalski — minimal number of animated elements, spring physics, no decorative loops.

### Spring config (canonical)

```ts
// Default — responsive, not bouncy
{ stiffness: 340, damping: 30, mass: 0.4 }

// Reduced motion — near-instant
{ stiffness: 520, damping: 60, mass: 0.4 }
```

### Easing (layout/opacity transitions)

```ts
ease: [0.22, 1, 0.36, 1]   // custom expo-out; duration: 0.22s
ease: 'easeOut'             // fast fades; duration: 0.15s
```

### Rules

1. **One hero moment per surface.** One thing animates when a view opens — not everything.
2. **Exit before enter.** Use `AnimatePresence mode="wait"` for state transitions.
3. **Scale + blur on icon swaps.** `{ scale: 0.82, filter: 'blur(3px)' }` on exit, reverse on enter.
4. **No infinite loops** unless they serve a functional signal (e.g., loading spinner, command border pulse).
5. **Always respect `prefers-reduced-motion`** — use `useReducedMotion()` to gate spring configs.

## Glass Morphism (Extension)

The extension popup overlays Jira's UI. Glass keeps it contextually grounded without hiding the host page.

```css
.glass {
  backdrop-filter: blur(var(--glass-blur, 40px));
  background: oklch(100% 0 0 / var(--glass-opacity, 30%));
  box-shadow: inset 0 0 0 1px oklch(100% 0 0 / var(--glass-border-opacity, 20%));
}
```

Dark mode Jira sidebar override: `backdrop-filter: blur(50px)`, transparent background — the extension blends into the host rather than fighting it.

## Component System

- **Shadcn** `new-york` style, `neutral` base color, OKLCH tokens throughout.
- **Icons:** Lucide React — consistent stroke weight, never mix icon families.
- **Button scale:** `xs` → `sm` → `default` → `lg`; square `icon-*` variants. Use the smallest size that remains tappable.
- **Empty states:** `<Empty>` compound component (EmptyHeader, EmptyTitle, EmptyDescription, EmptyMedia). Never use raw text + centered div.
- **Data slots:** `data-slot="*"` attributes on components — use these for scoped CSS overrides, not className hacks.

---

## Command Palette (Linear-style)

The popup's core interaction is a command palette. Styled via `linear-command.css`:

- Background: light gray scale (`--gray3` to `--gray12`)
- Selected state: `#eef2ff`
- Transition: `transition-all 150ms`
- cmdk selectors: `[cmdk-root]`, `[cmdk-input]`, `[cmdk-item]`, `[cmdk-group]`

**Rule:** command items should feel instantaneous. Never add loading states to filtering/search — debounce the network call, not the UI response.

## Anti-patterns

| Never do this | Do this instead |
|---------------|-----------------|
| Purple-on-white hero gradients | Stone/neutral palette with typography as the hero |
| Animate every element on mount | One coordinated stagger or a single hero reveal |
| Full-page loading skeletons | Optimistic UI + inline spinners only where needed |
| Cluttered toolbars | Progressive disclosure, keyboard shortcuts |
| Color-coding statuses with 6+ hues | Shape + text label; color only for pass/fail/warn |
| Font sizes below 11px | 12px minimum in extension; 14px minimum in website |
| Pill buttons on action items | Rounded-md at most; pills only for tags/chips |

---

## Design Checklist (before shipping UI)

- [ ] Does it work keyboard-only?
- [ ] Does it look right at 100%, 125%, and 150% zoom?
- [ ] Does it respect `prefers-reduced-motion`?
- [ ] Is there at most one animated element per surface on first render?
- [ ] Does it work in both light and dark mode?
- [ ] Are all interactive elements ≥ 24px tap target?
- [ ] No new colors introduced outside the token set?
